# Event Horizon

Der **50%-Punkt zwischen zwei gestackten Liquidity Pools** (z.B. zwei Sellside-Pools). Dient als
Entscheidungs- und Partial-Profit-Marker:

- Wird der erste Pool erreicht, können dort bereits **Teilgewinne** mitgenommen werden.
- Closed Preis **unter** (bzw. über, spiegelbildlich) dem Event Horizon, steigt die
  Wahrscheinlichkeit deutlich, dass auch der **zweite Pool** erreicht wird — der Event Horizon
  selbst eignet sich ebenfalls als weiterer Partial-Punkt.
- Wird auch genutzt, nachdem ein klarer [[AMD Cycle (Accumulation – Manipulation – Distribution)|DOL]]
  bereits erreicht wurde, um bei einem Best-Case-TP-Szenario noch zusätzliche Partials zu sichern.

## Partial *vor* dem Event Horizon, wenn ein altes Low dazwischenliegt (2026-Ergänzung)

Aus [[2026-07-02 - Missed Entry How To Navigate The Same Trade Idea (Source)|der Videofassung]] —
eine Ausnahme von „am Event Horizon Teilgewinne nehmen":

Liegt der zweite Pool **knapp unterhalb eines alten Lows**, verschiebt ICT den Teilgewinn bewusst
**nach oben, kurz vor** den Event Horizon:

> *„I want to kind of like take it off **just before** we get to it, because this down here is just
> below the old low. So I'm factoring that in by taking a partial **just above** what would be
> event horizon."*

Logik: Das alte Low ist selbst eine Liquiditätsmarke, an der eine Reaktion einsetzen kann, bevor
der rechnerische Event Horizon erreicht ist. Der Event Horizon bleibt der Rechenwert — der
**Ausführungspunkt** wird um die dazwischenliegende Struktur nach vorne korrigiert. Deckt sich mit
der Regel „Exit-Präzision ist unwichtiger als Entry-Präzision" in
[[Missed Entry Trade Management Playbook]].
